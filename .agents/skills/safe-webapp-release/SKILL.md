# 前提

- 開発環境と公開環境は、ソース・設定・DB・アップロード領域を分ける。
- ブランチ名、デプロイ先、DB接続情報、秘密情報は対象プロジェクトの安全な設定から取得し、スキル本文やログに書かない。
- 公開環境のデータを削除、置換、全面同期しない。必要な場合は対象、バックアップ、影響範囲について明示的な承認を得る。
- 公開反映は、依頼者が公開反映を明示した場合だけ行う。

# 手順

1. リポジトリの作業ブランチ、作業ツリー、リモート追跡ブランチを確認する。
2. リモートの開発・公開ブランチ間の差分を確認し、別開発者の先行変更を一覧化する。
3. 開発環境でビルド、型検査、関連テストを実行する。失敗した検査を隠したまま反映しない。
4. DB差分を確認する。スキーマ変更、初期データ投入、運用データ変更を分け、運用データの変更は別途報告する。
5. 開発環境へ反映し、認証が必要な主要画面を実際の利用経路で確認する。
6. 公開依頼がある場合だけ、公開ブランチへのマージ前に次を報告する。
   - 反映対象コミット
   - ソース差分
   - DBスキーマ差分
   - DBデータへの影響
   - 未確認事項とロールバック方法
7. 公開ブランチへ反映し、指定されたCI/CDまたはデプロイ手順を実行する。
8. 公開URLのHTTP応答、ログイン、変更画面、保存処理、再読み込み後の永続化を確認する。
9. 実施結果として、コミット、デプロイ結果、DB変更の有無、確認URL、残課題を報告する。

# 注意点

- `main`へのpushや本番DB操作を、単なる「開発開始」「差分確認」から推測して実行しない。
- 開発DBを公開DBへコピーする場合は、通常のデプロイとは別のデータ移行作業として扱う。
- マイグレーションは後方互換性を確認し、可能な限り追加・拡張を先に行う。破壊的変更は段階化する。
- デプロイ成功、ページ表示、HTTP 200だけでは保存成功とはみなさない。認証付き操作と再読込確認を行う。
- 秘密情報、個人情報、顧客データ、DBダンプ、秘密鍵をコミットやログへ出さない。
