description: 静的サイトやPHPサイトで管理データが消える・保存されない問題を、ファイル保存・権限・容量・ログから調査するときに使う。
---

# 前提

- DBを使っていない構成では、状態JSON、CSV、アップロードファイル、ログの保存先を分けて確認する。
- 本番データを直接初期化せず、最初に読み取り調査とバックアップを行う。

# 手順

1. `state.php`、認証、アップロード、状態データの保存先と書込処理を確認する。
2. サーバー容量、inode、ディレクトリ権限、所有者、PHP実行ユーザーを確認する。
3. 保存前後のファイルサイズ・更新日時・JSON妥当性を記録する。
4. 一時ファイルを書き、同一ディレクトリ内で原子的にリネームする方式を検討する。
5. 操作日時、対象ファイル、成功・失敗、HTTPステータス、例外を個人情報なしでログに残す。
6. ログと一時ファイルは保持期間を決め、期限を超えたものだけ定期削除する。
7. 削除前に対象範囲を限定し、状態データ・設定・認証ファイルを除外する。
8. 再読込、ブラウザを閉じて再表示、別端末からの表示で保存結果を確認する。

# 注意点

- `file_put_contents` の戻り値、`flock`、JSONエラー、HTTPレスポンスを必ず確認する。
- ログにパスワード、APIキー、顧客情報、予約本文を記録しない。
- 容量対策の自動削除は、バックアップと保持期間を定義してから有効化する。
