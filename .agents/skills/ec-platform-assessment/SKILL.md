# ECプラットフォーム選定・移行調査

ECプラットフォームを選定・比較するときに、現状のECサイトと業務を整理し、比較表と判断材料を依頼者に示すための調査手順。実際の移行作業の実施は対象外。

## いつ使うか

- ECサイトの乗り換え・移行を検討しているとき
- 複数のECプラットフォームを比較したいとき
- 現在のEC環境の課題や、見積機能・会員機能・個人情報・保守負担を整理したいとき

## 手順

1. **現状と要件のヒアリング**
   - 現在利用中のECプラットフォームと、変更したい理由を確認する。
   - 移行で失いたくない機能、追加したい機能、業務上の必須条件を一覧にする。
   - 支払い方法、会員・顧客データの規模、発送・在庫の業務フローを確認する。

2. **候補プラットフォームの抽出**
   - 要件に合うプラットフォームを3〜5つ程度抽出する(例: 主要カートサービス、EC構築パッケージ、CMS内ECプラグイン、カスタム開発)。
   - 情報は、公式ページ・公式ドキュメント・料金ページ・公式ブログ・公式サポート掲示板・公式パートナー資料を最優先とする。

3. **必須条件と加重評価を分ける**
   - 必須条件(業務上外せない機能や、個人情報の取り扱い方針)は、価格などの高評価で相殺しない。必須条件が未確認なら「条件付き・確認待ち」と評価する。
   - 必須条件以外の項目は、依頼者の業務上の優先順位を確認したうえで加重をつける。

4. **比較軸の確定と資料集め**
   - 次の比較軸で評価を進める。各項目の出典URLと確認日を必ず記録する:
     - 見積機能、会員機能、商品管理、注文・在庫連携、配送・決済連携
     - 個人情報の取り扱いと管理画面の権限分離
     - データ移行の制約(手順5参照)
     - 月額・初期・移行の費用体系、取引手数料、追加費用が発生する項目
     - 保守・運用の負担(アップデート、脆弱性対応、サポート体制、公式パートナーの有無)
     - 公式サポート期限・終了予定、非推奨化の予定の有無

5. **移行制約の確認項目**
   - 会員認証・決済情報の引継ぎ方法と、引き継ぎ後に再設定が必要な項目。
   - 会員・商品・注文データ間の関連と照合方法。
   - 既存URLの維持、リダイレクト設定、外部連携(API、決済、配送)の引き継ぎ。
   - 許容できる停止時間と、移行中の受注の扱い。
   - データ形式、移行ツール・API・CSVの有無、外部支援の必要性。

6. **汎用的な確認ポイントの洗い出し**
   - 機能面: 実装済みか、設定だけで対応できるか、追加カスタマイズが必要か。
   - データ面: 現在のデータが移行先でそのまま使えるか、照合方法。
   - 個人情報面: 保存場所、暗号化、第三者提供の有無、利用規約とプライバシーポリシーで扱いが変わる箇所、管理画面の権限分離。
   - 費用面: 同じ利用規模・比較期間・税条件で比較する。初期費用、月額費用、取引手数料、追加機能・テンプレート・保守の費用、移行作業自体の費用。
   - 保守面: 公式アップデートの頻度、脆弱性対応の速さ、公式パートナー・公式コミュニティの支援の有無、依頼者が自分で保守できるか。

7. **比較表の作成**
   - 軸 × 候補の比較表を作り、各セルに次の対応区分と記録を付す:
     - 対応区分: 標準／プラン依存／外部拡張／個別開発／不可／未確認
     - 記録項目: 適用条件、公式URL、確認日、未確認事項と確認方法
   - 未確認を不可として扱わない。確認できていない項目は「未確認」と明記し、確認方法(公式窓口、試用環境、公式ドキュメント)を併記する。
   - 業務上の優先順位や依頼者の判断は依頼者に確認し、製品仕様そのものは公式窓口・試用環境・公式ドキュメントで確認する。

8. **リスクと未確認事項の整理**
   - 料金・サポート期限・脆弱性情報は変わりやすいので、必ず「この情報は{確認日}時点」と記録する。
   - 公式ページだけでは確定しない項目(カスタマイズ範囲、移行データの照合、特定機能の有無)は、確認先と質問文を添えて依頼者に提示する。

9. **提案形式**
   - 依頼者には、比較表+リスク・未確認事項+根拠付きの推奨案を簡潔にまとめて提示し、最終選定は依頼者に委ねる。

## 注意点

- 移行元・移行先のプラットフォーム名、契約・運用・社内情報は、スキル本文に書かず、実行時の案件ごとの情報として扱う。
- 料金・サポート期限・脆弱性情報は変動するため、実行時刻の公式情報を必ず再確認する。
- 複数の候補で評価が拮抗する場合は、依頼者の業務上の優先順位を確認してから加重を決める。
- 根拠と未確認事項を示して推奨案を提示し、最終選定は依頼者に委ねる。
